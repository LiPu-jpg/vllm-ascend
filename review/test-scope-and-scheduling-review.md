On arch22, InitCalcParamsEach accumulates one task per actual query and sets avgBaseNum to1 when total work does not exceed GetBlockNum. SplitBalanced sets mBaseSize to gSize, including G128, so a query group is not multiplied by query-head count on this path. A5 has a separate head-splitting rule and is excluded. For valid TND metadata, actual query work is at most tensor T. If T is below hardware core count, both original and bounded launches retain avgBaseNum1 and identical valid-query ownership. If T is at least hardware core count, the count stays unchanged. The guard excludes other layouts, RoPE, non-unit sparse blocks and other KV-head counts. Existing host validation accepts G1..64 or128.

Kernel InitWorkspace advances per-core regions using GetBlockNum; the host allocates those same per-core regions using coreNum_. Replacing the allocation count with the actual bounded launch aligns this count with the kernel stride without changing any per-core size. The system API workspace remains unchanged. Static workspace calculations cover166,400 combinations; numerical head tests include G1/7/16/31/63/128. Tensor padding and device-length changes are exercised separately. The source review establishes the scheduling argument, not physical A3 performance or all-model correctness.
